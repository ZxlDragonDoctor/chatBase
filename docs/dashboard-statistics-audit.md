# 首页统计口径审查

审查日期：2026-10-10
范围：`GET /api/statistics/system/overview` 及首页展示字段。本文记录当前实现和建议，不表示后端统计已修复。

## 已核对的计算

- 今日会话数和 Token 按 `kb_conversation.create_time` 从当天零点（含）到次日零点（不含）筛选。
- 30 天活跃统计从今天往前 29 天的零点开始，到次日零点前结束；活跃群组只筛选 `conversation_type = 'group'`。
- 管理员默认统计全部数据；普通用户按其拥有的应用和群组筛选。

## 发现的问题

### 群组和用户标识没有包含平台

活跃群组按 `group_id` 去重，活跃用户按 `user_id` 去重；个人统计也只用 `group_id` 过滤消息。数据库按 `(platform, group_id)` 和 `(platform, user_id)` 建立唯一标识，因此不同平台上相同的 ID 会被合并。对于个人统计，只按群 ID 过滤还可能把其他平台同 ID 群组的消息计入当前用户的聚合结果。

### 个人统计没有覆盖所有可见群组

统计服务只收集由当前用户创建或绑定到其应用的群组 ID，没有纳入 `created_by IS NULL` 的未认领群。IM 控制台的可见规则包含未认领群，因此首页的个人消息数和活跃度可能低于用户在控制台可见的范围。

## 修正建议

1. 统计查询以 `(platform, group_id)` 作为群组标识，并以 `(platform, user_id)` 作为用户标识；不要只按裸 ID 去重或筛选。
2. 个人统计的群组集合应沿用 IM 控制台的可见范围，并保留用户自己的应用绑定过滤。
3. 为跨平台同 ID 和未认领群增加统计回归用例，分别验证管理员和普通用户的范围。

本轮工作只调整前端界面，没有修改服务端指标定义。修正这些查询前，应先确认产品上“个人统计”是否也应包含全部未认领群，因为该规则会影响用户看到的统计范围。
