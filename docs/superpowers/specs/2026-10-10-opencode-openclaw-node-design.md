# OpenClaw 式 opencode 远程节点设计

- 日期：2026-10-10
- 状态：用户已批准，已实施
- 范围：新增兼容式远程节点通道，并在私聊管理页加入节点管理

## 背景

ChatBase 当前让 QQ、微信和企微的私聊处理器通过 `ImConversationService.isOpencodeBound()` 判断是否转给 opencode。`OpencodeService` 通过 HTTP 操作 OpenCode API。远程访问可使用直连 HTTP，或由 `bridge/opencode-bridge.mjs` 主动连接 `/opencode/bridge`，再代转发 HTTP 方法、路径和请求体。私聊绑定以 `app_id = -1` 表示本地 opencode；管理员在私聊管理页配置绑定。

现有桥接解决了本机无需开放入站端口的问题，但服务器把 OpenCode API 当作通用 HTTP 代理面。目标是增加类似 OpenClaw Gateway/Node 的连接、配对、能力批准和调用路由，同时保持当前用户与机器人流程可用。

## 目标

1. 让本机 opencode Agent 主动通过 WSS 连接 ChatBase，服务器不要求本机开放入站端口。
2. 通过单次配对和管理员批准登记多台本机节点，并按私聊会话显式选择节点。
3. 使用受限的、带类型的 RPC 调用本机 OpenCode API，不暴露任意 HTTP 路由或 shell 命令。
4. 保持现有 Dify、opencode 直连、旧反向桥接、IM 机器人配置和终端用户聊天入口兼容。
5. 在现有私聊管理页提供节点配对、审批、状态查看、撤销和会话绑定，不新增导航入口。

## 非目标

- 实现与 OpenClaw Gateway 的线级协议兼容。
- 在此阶段重做所有控制台页面或开展未限定范围的全站功能重构；这些工作应独立盘点、排序并分期。
- 允许节点执行通用 shell 命令或接受任意 HTTP method/path/body。
- 将 QQ、微信、企微机器人本身与本机电脑直接配对。机器人消息仍先进入 ChatBase。
- 在节点离线时缓存任务、自动切换到其他节点或静默改走旧执行端。

## 方案概览

ChatBase 保持现有 Gateway 职责：接收平台消息、维护会话和权限、选择执行端并把回复交回原平台。每台本机电脑运行 Node Agent。Agent 主动连接 ChatBase 的新节点 WebSocket 端点，并在本机访问 `opencode serve`，默认地址为 `http://127.0.0.1:4096`。

新通道与现有通道并行运行：

| 会话绑定 | 执行路径 |
|---|---|
| 普通应用绑定 | 当前 Dify 路径 |
| `app_id = -1` 且 `opencode_node_id IS NULL` | 当前 opencode 直连/旧桥接路径，继续遵循 `opencode.bridge.transport` |
| `app_id = -1` 且 `opencode_node_id` 有值 | 新的受限 Node RPC 路径 |

管理员逐个把会话绑定到新节点。旧会话不会自动改变目标；迁移期间可继续使用旧 Agent 和配置。不会因新节点断线而改走另一台电脑或旧链路。

## 配对、身份与授权

1. 管理员从现有私聊管理页生成短时、一次性配对码。默认有效期为 10 分钟，服务器只保存不可逆校验值。
2. 本机 Agent 使用配对码和本机生成的稳定节点标识主动连接新 WSS 端点。配对凭据不放在 URL 查询参数中，也不写入日志。
3. 配对码校验成功后，ChatBase 登记待审批节点并发放该节点专属凭据。节点显示名称、操作系统、Agent 版本和声明的能力。凭据在待审批期间只允许验证身份和发送心跳，不能执行 RPC；Agent 可在审批期间保持连接或用该凭据重连。
4. 管理员批准或拒绝该节点声明的能力集合。批准后，节点凭据可用于正常连接和已批准 RPC；服务器仍只接受已批准能力。撤销节点会使凭据失效并关闭活动连接。
5. 新增能力或扩大能力面时重新进入待审批状态；已经批准且仍声明的能力继续按服务器策略生效。

配对与节点管理 API 只允许管理员访问。Node Agent 的本地配置保存节点 ID、凭据和 OpenCode 地址，并限制本机文件权限；服务器保存凭据校验值。节点连接必须先完成身份验证，之后才允许注册或调用。

## RPC 能力与数据流

第一版仅声明 `OpencodeService` 当前需要的 OpenCode 操作：

- 健康状态检查；
- 会话列表、读取和创建；
- 提交 prompt；
- 读取消息；
- 读取并回复 OpenCode 交互问题。

协议使用版本号、请求 ID、命令名、参数和截止时间。Agent 返回进度、结果或结构化错误；服务器在取消或超时后尽力发送取消通知。Node Agent 将每个命令映射到固定的本地 OpenCode API 路由；未登记命令和任意路径均拒绝。

请求流：

1. QQ、微信或企微机器人沿现有入口把私聊消息交给 ChatBase。
2. 平台处理器沿用现有 `OpencodeService` 调用路径。
3. ChatBase 按 `im_conversation.opencode_node_id` 选择已批准节点，并通过其 WSS 连接发送 `opencode.prompt.submit` 等 RPC。
4. 本机 Agent 调用环回地址的 OpenCode API，按现有行为收集回答和交互问题。
5. 结果通过同一连接返回 ChatBase，由原机器人按现有渠道回复原私聊。

配对是按电脑进行；管理员绑定是按 IM 私聊进行。因此一台电脑可以服务多个平台上的多个私聊。其他已接入 ChatBase 的机器人也沿用相同路由，不需要自己运行配对协议。此阶段只把现有私聊绑定到节点，群聊保持现状。

## 会话与存储

- 新增 `opencode_node` 持久表，保存稳定节点 ID、显示名、凭据校验值、能力声明及批准面、启停状态、创建人、创建/更新时间和最近心跳时间。在线状态结合活动 WebSocket 计算，不单独作为持久事实。
- `im_conversation` 增加可空 `opencode_node_id` 和索引。空值表示继续使用旧执行路径；非空值表示走新节点。
- 更新 `ImConversation`、摘要 DTO/Mapper、初始化 SQL 和既有数据库升级 SQL。
- 节点在线连接与未完成 RPC 保存在服务进程内。每个请求使用唯一 ID；节点断开时完成该节点所有待处理请求并返回可理解的错误。
- 新节点的 OpenCode session 映射使用 `(nodeId, conversationId)` 作为 Redis 键空间，避免不同电脑的 OpenCode session ID 混淆。旧 Redis key 保持读取兼容；绑定切换后不把一个节点上的 session ID 发给另一个节点。

## IM 绑定与界面

在 `ImSingleChatPage.vue` 中增加紧凑的节点管理区域，延续当前页面的视觉变量和组件风格：

- 展示在线/离线、最近心跳、平台和已批准能力；
- 生成配对码，并列出待审批节点及其能力申请；
- 提供批准、拒绝、重命名和撤销操作；
- 选中私聊后，管理员可以绑定一个已批准节点。节点列表显示在线状态；离线节点仍可查看，选择时明确提示暂不可执行。

节点管理、配对审批和 opencode 绑定均为管理员操作。普通用户继续通过现有 QQ、微信或企微入口聊天，不增加配对步骤。绑定普通应用或未绑定的私聊仍走现有业务路径。

## 兼容与迁移

- 保持 `/opencode/bridge`、现有 V1 消息格式和 `bridge/opencode-bridge.mjs` 在迁移期间可用。
- 新节点使用独立 WebSocket 端点和协议版本，避免旧 Agent 与新节点握手混淆。
- `opencode.bridge.transport=direct|bridge|auto` 的旧语义不变。未设置节点 ID 的本地 opencode 绑定继续由旧 transport 处理。
- 新节点端点使用 `/opencode/node`；部署配置中的 Nginx/WebSocket 转发和部署文档同步加入该端点，旧 `/opencode/bridge` 路径保持不变。
- `app_id = -1` 仍标识 opencode 绑定；新节点只通过新增的 `opencode_node_id` 选择。
- 不自动把旧会话迁到某台新电脑。管理员可以在私聊页逐个切换；撤销或删除新节点不会把会话静默改绑到其他目标。
- 不更改机器人配置、现有 webhook、通道消息格式、`/new`、`/session`、`/model` 等命令入口。高层 `OpencodeService` 保留这些业务行为，将其所需 API 操作分别映射到旧 transport 或新 typed RPC。

## 在线状态、断线与错误处理

- Agent 使用指数退避重连并发送心跳；服务端以最近心跳判定在线状态。页面允许管理员刷新状态。
- 会话绑定的节点离线时，任务立即返回包含节点名称和离线状态的提示，不入队、不自动切换。
- 已派发后遇到断线、超时或取消时，不自动重新提交 prompt，避免重复执行写代码任务。返回可理解的失败结果，服务端日志不记录完整节点凭据或 JWT。
- 无效/过期配对码、未批准能力、撤销凭据和不兼容协议均拒绝执行，并给出管理员可采取的下一步。
- OpenCode Basic Auth 凭据仅由本机 Agent 访问本机服务；ChatBase 不需要通过节点 RPC暴露该密码。

## 验收场景

实现后按以下行为进行验证；此阶段只定义验收条件，不创建或执行测试：

1. 原有 Dify 私聊、opencode 直连和 V1 旧桥接按原配置继续工作。
2. 管理员生成配对码、Agent 连接、节点待审批、批准后可重连；撤销后连接不能恢复调用能力。
3. 非管理员不能生成配对码、审批/撤销节点或更改 opencode 绑定。
4. 已批准节点绑定到 QQ、微信和企微私聊后，任务在指定电脑的 OpenCode 上执行，回复回到正确平台和会话。
5. 一台节点可以处理多个会话；多个节点之间不共享 OpenCode session 映射。
6. 新节点离线、能力未批准或 RPC 超时时，系统明确失败，不排队、不自动故障转移，也不污染旧执行路径。
7. 旧 `app_id = -1` 会话未指定节点时仍走旧 transport；显式设置节点后才使用新 RPC。
